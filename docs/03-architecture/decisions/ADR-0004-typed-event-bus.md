# ADR-0004: Типізована event bus + global store для крос-MFE комунікації

## Статус

Accepted

## Контекст

MFE (`pages-mfe`, `user-mfe`) завантажуються незалежно й не повинні мати прямих імпортів один одного. Водночас їм потрібно обмінюватись подіями (логін/логаут користувача, глобальні нотифікації) і читати спільний стан (поточний користувач, тема). Класичний спільний React-контекст погано лягає на федерацію: різні MFE можуть отримати різні екземпляри провайдера.

## Рішення

Виділено окремий пакет **`@repo/events`** з двома примітивами:

- **Event bus** (`event-bus.ts`) — типізований `emit`/`on`/`once`/`off` поверх класу `TypedEventBus`, збереженого як singleton на `window.__CINEPULSE_EVENT_BUS__`. Контракт подій жорстко типізований через `EventMap` (`user:login`, `user:logout`, `user:update`, `navigation:change`, `notification:show`, `mfe:ready`, `mfe:error`). Фабрики `createTypedEmitter` / `createTypedListener` дають типобезпечні хелпери.
- **Global store** (`store.ts`) — singleton `window.__CINEPULSE_STORE__` зі станом `{ user, isAuthenticated, theme }` і діями `setUser`/`updateUser`/`setTheme`/`reset`.

Singleton саме на `window` гарантує єдиний екземпляр навіть якщо федерація завантажить пакет двічі. `@repo/events` оголошений shared у всіх `vite.config.ts`.

## Наслідки

**Плюси:**
- Повна типобезпека подій — payload кожної події перевіряється компілятором.
- Нульова зв'язність між MFE: спілкування лише через контракт `EventMap`.
- Стійкість до дублювання екземплярів завдяки `window`-singleton.

**Мінуси / компроміси:**
- Global store **не реактивний «з коробки»** для React — немає готового хука-підписки; наразі використовується переважно як шина стану/подій. Реактивну інтеграцію (напр. хук `useStore`) доведеться додати при реалізації Profile/Settings.
- Стан на `window` — глобальний і не ізольований для тестів (потребує явного `reset()`).
- Розширення контракту (`EventMap`) вимагає узгодженого оновлення в усіх споживачах.
